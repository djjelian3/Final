# iPrime Vision

A Flask-powered eye care and eyewear management application for patients and clinic administrators.

## Features

- Patient registration and sign in
- Patient dashboard and profile pages
- Appointment booking and upcoming appointment list
- Admin dashboard
- Patient, prescription, appointment, billing, eyewear, inventory, notification, report, and settings pages
- SQLite database initialized automatically on application startup
- Responsive patient and admin interfaces

## Requirements

- Python 3.10 or newer recommended
- Flask 3.x

## Setup

From the `iprime-vision` directory, create and activate a virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install the dependencies:

```powershell
pip install -r requirements.txt
```

## Run The Application

```powershell
python app.py
```

Open the application at <http://127.0.0.1:5000>.

The SQLite database is stored in `iprime_vision.sqlite3`. Required tables and demo users are created automatically when the application starts.

## Deploy With Render and Neon

1. Push the contents of this directory to a GitHub repository.
2. Create a PostgreSQL project in Neon and copy its pooled connection string.
3. In Render, choose **New + > Blueprint** and select the GitHub repository. Render will use `render.yaml`.
4. In the Render service environment variables, set `DATABASE_URL` to the Neon connection string. `SECRET_KEY` is generated by Render automatically.
5. Deploy the service. The build command installs `requirements.txt`, and the start command runs `gunicorn app:app`.

Do not commit `.env` or paste its contents into GitHub. Render environment variables replace the local `.env` file in production. If the repository contains an outer folder, set Render's Root Directory to the folder containing `app.py`, `requirements.txt`, and `render.yaml`.

## Main Routes

### Pages

- `/` - Public homepage
- `/auth/auth.html` - Sign in and account creation
- `/patient/dashboard.html` - Patient dashboard
- `/patient/appointment.html` - Appointment booking
- `/admin/dashboard.html` - Admin dashboard

### API

- `POST /api/auth/signup` - Create a patient account
- `POST /api/auth/login` - Sign in
- `POST /api/auth/logout` - Sign out
- `GET /api/auth/me` - Get the current signed-in user
- `PATCH /api/auth/profile` - Update the signed-in user's profile
- `GET /api/appointments` - List the signed-in patient's appointments
- `POST /api/appointments` - Book an appointment
- `POST /api/appointments/admin` - Create an appointment for an existing patient as an admin
- `PATCH /api/appointments/<id>` - Confirm, cancel, or update an appointment as an admin
- `DELETE /api/appointments/<id>` - Delete an appointment as an admin

## Development Notes

- Flask runs with `debug=True` when started through `app.py`.
- The application uses a development secret key in `app.py`; configure a secure environment-based key before deployment.
- Passwords are stored as Werkzeug hashes; plain-text passwords are never saved for newly created users.
- Appointment date and time combinations are unique in the database, preventing double booking of the same slot.
